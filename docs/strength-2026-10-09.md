## Castling legality correction

Replayed fresh losses `IGpoFQPn`, `5kUsoO5c`, and `GWTjIExF` from their full
UCI streams. Before correction, `GWTjIExF` failed replay at Black's legal
15...O-O-O. The bishop on d6 attacks b8, which is outside the king's path.
The old castling check required b8 to be unattacked. It also incorrectly
required the kingside rook's square to be unattacked, allowed friendly rooks
to block the path, and accepted a missing or wrong-type corner rook.

`King.canCastle` now requires the king's home square, the matching friendly
corner rook, and an entirely empty path between king and rook. It checks
enemy attacks only on the king's start, transit, and destination squares.
Castling rights remain enforced by the existing caller.

The targeted tests failed on the original implementation and passed after
correction. They cover both colors and castling directions, attacks on each
king-path square, attacked rook/b-file squares, blockers, absent and invalid
rooks, lost rights, and misplaced kings. An exact 30-ply game regression
checks the resulting castled FEN. All 83 post-build logged move streams replay
legally with the corrected binary.

Board, analysis, and server package tests passed. Targeted game lifecycle and
repetition tests passed. Focused board/analysis race tests, build, and
`git diff --check` passed. Full game-playing tests were stopped. The AI suite
completed with `TestAIBestMovesSame` explicitly skipped and one failure:
`TestABDADANullMoveGuardFindsBishopDefense`, selecting `g7g6` with score 465.
The same test reproduced the identical failure in a clean `5a37c8d` worktree.
The complete AI suite is not reported as passing.

Added independent depth-three perft regressions against the standard reference
positions. All five match: initial position 8902, Kiwipete 97862, rook/pawn

## King-check throughput

A production-build profile of the three late positions attributed 12.81%
of sampled CPU to `Board.IsKingInCheck`. That method built the entire enemy
attack map to test one square. It now calls the existing geometric
`isKingInCheckFast` helper, already used for move legality and SEE.

The perft tests now compare both colors' check status against the original
attack-map method at every node, including leaves. All five standard
depth-three counts remain correct. The same comparison also passes on all
94 strength-corpus roots, the 20 newly extracted loss positions, and their
legal children. Board, analysis, and server tests and the focused analysis
race run pass. The AI suite, with `TestAIBestMovesSame` skipped, still fails
only the baseline bishop-defense regression with `g7g6`, score 465.

The uncached king-check microbenchmark dropped from approximately 1,020 ns
and two allocations to 79 ns and zero allocations. At fixed depth three,
one worker selected identical moves, scores, and node/pruning counters on
all 94 positions. Total search time fell from 58.760 to 52.293 seconds:
11.0% less time, or 12.4% more throughput. These are single paired search
runs; the microbenchmark was repeated three times. An interrupted,
unbounded depth-four run is excluded.
