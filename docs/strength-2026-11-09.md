## Mechanism and candidate

An isolated source overlay traces a different, faster mating branch after
exf3 Rxe7 Rxe7. Rb8+ is reduced by one ply. After ...Kf7, futility prunes
Qf5# together with other quiet checks at depth two: static score -353,
margin 300, alpha 201, beta 202. Stockfish confirms Rb8+ forces mate;
its longest line is ...Qd8 Rxd8+ Kf7 Qf5#.

Futility classified every quiet check like a positional move, so even an
immediate mate could disappear behind a static material deficit. The
candidate checks would-be futility prunes on a copied board and preserves
moves that checkmate. It reuses legal-move generation with the actual last
move. Other quiet checks keep the existing selective-search policy.
The exact-game depth-seven regression covers both the original Black
position and its vertically mirrored, color-swapped White position.
Existing tactical assertions remain unchanged.

Broader changes were rejected locally. Exempting every checking move fixes
the new mate but fails the unchanged bishop-defense test with g7g6.
Capping checking LMR reductions at one alongside that exemption still fails.
Exempting checks following a check evasion passes the first bishop fixture
but fails the second with h7h6. None of these broader policies is retained.
The immediate-mate guard passes the new original-position test and both
unchanged bishop-defense positions, plus knight retreat.

The optimized candidate chooses Qd8 in all three single-worker and all
three four-worker six-second searches. Each finishes depth seven.
This establishes a repeatable correction on the live-game position,

## Exact log context recovery

The original log-context parser matched only five of ten scanned mistakes.
The cause was event ordering: Lichess can deliver the bot's own-move
`gameState` before its HTTP move response arrives. Reading the latest state
at response time then shifts the position by one ply and clears search
iterations. The corrected diagnostic captures root state at `player thinking`
start and retains it through the move response. It matches all ten scan
targets by game ID, pre-move ply, and posted move, without running an engine.
Contexts and exact logged budgets are preserved in
`testdata/lichess_2026_11_09_loss_log_context.json`.
