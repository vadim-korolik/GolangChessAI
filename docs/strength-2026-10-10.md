## Move-ordering correction, not deployed

`Board.GetAllMoves` used `sort.Slice` to swap moves while its comparator read
an unswapped array of precomputed scores. A diagnostic found incorrect ordering
in 55 of 114 historical positions. The exact CdTsyKE6 regression requires
`e5f6`, `c3d5`, and `e3h6` to be the first three moves, ordered by capture score.
The original implementation instead put `e3h6` first.

The candidate keeps each precomputed score and move in one sortable record,
uses the existing `sort.Slice` policy, then copies the sorted moves into the
returned slice. Cached move lists remain protected by the existing copy.

## Busy transposition entry corrupts search windows

The Rc8 miss also reproduces without a clock: the eight-worker iterative
depth-nine search selects Rc8 at -653, while a fresh forced-Rc8 depth-nine
search sees a losing mate. An isolated instrumented search traced ten returned
infinity scores. Those scores hid both Ne4 and Ne6 mating continuations.

`ttRead` returns `OnEvaluation` for a busy same-depth exclusive probe. Such an
entry need not have a best move yet. `ABDADA` previously deferred this result
only if it carried a move; otherwise it searched children with the sentinel
as `best.Score`. The resulting invalid windows returned `NegInf`, whose
negation became `PosInf` and falsely refuted mating moves.

The correction returns the busy result before the move-dependent cutoff guard.
The existing second search pass handles deferred children with nonexclusive
probes. A synthetic busy, move-less entry reproduced the bug deterministically:
the original code searched 921 nodes and returned `PosInf`. The corrected code
must return `OnEvaluation` without searching children, in full and narrow
windows. A second regression runs the actual rook ending with eight workers
through depth nine and requires Kg5.

Matched isolated traces with the correction return no infinity scores and
select Kg5 at -1245. Trace instrumentation remains outside the main worktree;
its elapsed time and node counts are not throughput evidence. Focused TT,
quiet-mate, mate-safety, rook-activity, bishop-defense, and knight-retreat tests
pass together in 20.155 seconds. The complete AI package suite passes in
97.619 seconds with `TestAIBestMovesSame` explicitly skipped and existing
in-test skips retained. Targeted race checks covering both new TT regressions,
the forced-Kh5 mating-net test, and mate-in-one safety pass in 53.192 seconds.
